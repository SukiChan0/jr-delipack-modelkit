# Agent working rules

Read README.md, evidence/VALIDATION.md and docs/RELEASE_CHECKLIST.md first. These public project documents are self-contained; no private operational record or production-system access is needed to build or test the prototype.

Work only in this standalone prototype directory, outside every production Git tree and shared worktree. Existing websites, automation, credentials and commercial assets are not authorized targets. Never repurpose, rename, publish or write to a production scheduling repository. Before any authorized remote write, verify the exact target and clean public-file allowlist; do not blindly use the current origin or copy production Git history.

Never create a remote repository, push, change visibility, enable Pages or deploy without a separate explicit approval of the exact release. No production secrets, runners or deployment callbacks in this project.

Use the existing environment; no runtime downloads, paid services, secret reads or production API calls. Do not bypass local security policies. Keep provenance/license notices. Test claims must match executed evidence. No output overwrite, arbitrary recipe execution or image uploads.

The first phase is deliberately narrow. Do not silently turn manual tracing into claimed automatic reconstruction or revive a complete editor/platform scope.
